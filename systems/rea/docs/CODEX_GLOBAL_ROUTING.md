# REA entre conversas

O REA independente e disponibilizado como plugin `rea-independent` 0.1.1, com
rea-setup, rea-operacao e rea-fechamento-operacional. A skill de investigacao
`rea-engenharia-reversa-evolutiva` continua na entrada `.agents/skills` do repositorio.
Nao duplicar o motor nem confundir com o REA Lab antigo ou morluto/rea.

A orientacao global pode considerar REA em qualquer conversa, mas so executar
analise de codigo quando houver alvo autorizado e ferramenta realmente disponivel.
Perguntas sem alvo tecnico nao iniciam varredura de arquivos, agentes ou modelos.
Nao importar anexos de outras conversas e nao ampliar o root automaticamente.

O MCP local deve registrar o SDK existente por stdio com diretorio de entrada
isolado. Confirmar initialize, sete ferramentas, chamada read-only, hash e
negativa de escape; depois conferir o inventario do host. Configurado nao e
HOST_DISCOVERED. Uma nova sessao pode ser necessaria para carregar o MCP/Skills.

Na web, instalar Skills nao implanta o servidor. Exigir tunel privado autorizado,
chave runtime com Tunnels Read + Use em referencia segura, doctor, runtime pronto
e descoberta/chamada efetiva. Nunca gravar chave em Git ou argumento de comando.
O identificador/associacao do tunel da conta fica no recibo local, nao no plugin.

O fechamento operacional coordena os verificadores existentes e conserva os
gates de seguranca, rollback, revisao/merge por SHA e aceite. Os registros
operacionais privados permanecem no DataCenter REA. PRODUCTION_COMPLETE=NO.
