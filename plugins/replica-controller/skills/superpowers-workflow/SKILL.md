# Entrada independente Superpowers

Escolha e carregue a skill oficial instalada para a etapa. Reutilize decisões
e aprovações atuais. Conduza a implementação e a validação no escopo autorizado;
seleção de skill não é evidência de execução.

| Situação | Processo oficial |
|---|---|
| Ideia ou mudança com desenho indefinido | brainstorming |
| Necessidade de isolamento | using-git-worktrees |
| Trabalho de múltiplos passos com escopo entendido | writing-plans |
| Implementar sequencialmente | executing-plans |
| Comportamento que requer regressão | test-driven-development |
| Erro reproduzível ou falha de teste | systematic-debugging |
| Revisar uma alteração | requesting-code-review |
| Tratar feedback recebido | receiving-code-review |
| Confirmar resultado | verification-before-completion |
| Finalizar branch ou integração autorizada | finishing-a-development-branch |
| Criar/alterar skills | writing-skills |
| O próprio processo repetiu trabalho ou ignorou requisitos | diagnosing-superpowers |
| Descobrir o processo aplicável | using-superpowers |
| Tarefas independentes que justificam agentes autorizados | subagent-driven-development ou dispatching-parallel-agents |

Implementação sequencial é o padrão do usuário. Não despache agentes, mude
modelo/conta, instale serviços ou publique só porque uma skill sugere. Preserve
instruções do projeto. Aplicar a etapa pertinente não significa executar todas.

Este modo não exige Replica nem Arena. Sem o plugin oficial no host, registre
a dependência ausente e não alegue ter invocado a skill. Para uso conjunto,
encaminhe a replica-power-arena. Na web, disponibilidade e execução devem ser
conferidas ali. Não cria rotina periódica; trabalho ocorre durante o pedido.
