# Entrada independente Replica

Ao receber esse tipo de pedido, selecione a etapa pelo objetivo e pelo estado
real do projeto. Execute o trabalho pertinente até o aceite, com as ferramentas
disponíveis; não se limite a devolver uma lista de skills.

| Necessidade | Skill a carregar |
|---|---|
| Entender a referência | replica-recon |
| Definir dados e contratos | replica-architect |
| Definir interface e acessibilidade | replica-design |
| Construir o fluxo visível | replica-build |
| Dados reais, login e integrações | replica-backend |
| Reproduzir defeitos e testar fluxos | replica-test |
| Comparar requisitos com a referência | replica-diff |
| Priorizar problemas reais dos usuários | replica-entrepreneur |
| Identidade própria | replica-brand |
| Preparar comunicação do lançamento | replica-launch |
| Publicar no destino autorizado | replica-deploy |

Procure a skill irmã pelo nome e leia somente a etapa necessária. Reutilize
recon, contratos e critérios atuais. Se faltarem requisitos essenciais, obtenha
somente a informação que impediria uma decisão correta. Não percorra as onze
etapas para corrigir um defeito pontual. Um fluxo deve incluir estados de erro,
dados e testes pertinentes, não apenas aparência.

Este modo não exige Superpowers ou Arena. Se o usuário pedir o conjunto,
encaminhe a replica-power-arena. Preserve identidade e implementação próprias,
origens oficiais, trabalho humano, conta e modelo. Instalação não prova execução.
Sem ferramenta necessária, registre BLOCKED/NOT_RUN. Após duas tentativas da
mesma falha, registre a causa e prossiga somente com tarefas independentes.

No Codex Windows, adapte npm para npm.cmd e encontre o Python real. Na web,
use apenas arquivos e conectores expostos; não presuma acesso à máquina.
Nenhum serviço permanente, agendamento ou chamada de modelo extra é criado.
