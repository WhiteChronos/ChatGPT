# CONTINUOUS IMPROVEMENT

## Trigger events
- physical block looks generic compared with manufacturer/reference DXF;
- curves/details were lost in conversion;
- ISO does not match orthographic views;
- object and symbol were mixed;
- better CAD/BIM source is found;
- user supplies a higher-fidelity benchmark.

## Cycle
1. Capture defect and evidence.
2. Classify: identity, source, conversion, geometry, view-set, symbol, QA, workflow.
3. Find root cause.
4. Make the smallest reusable improvement.
5. Test failing case + at least one known-good benchmark.
6. Record before/after entity types, audit status and dimensional comparison where useful.
7. Update skill/workflow/memory only after validation.

## Important
Entity count can reveal oversimplification but is not a quality target. The primary criterion is fidelity to authoritative geometry.
