# GitLab Contingency CI Resilience Drill

## Purpose

Exercise provider redundancy without changing repository authority or executing
release/production actions. The drill verifies that GitLab can supply additional
technical evidence for the exact same immutable commit while GitHub remains the
sole authority.

## Preconditions

- The reviewed one-way mirror worker is bound to an independent authorized host.
- GitLab project `chronoswhite-group/ChronosWhite-project` contains the target ref.
- Source, target and CI subject use the exact same 40-character Git commit SHA.
- The GitLab pipeline definition at that SHA has passed static contract review.
- No authority-changing or production credential is present in the contingency path.

## Scenario A — GitHub Actions runner assignment unavailable

1. Select an eligible non-production test ref at an immutable GitHub SHA.
2. Simulate only GitHub Actions runner-assignment unavailability. Do not make the
   GitHub repository itself unavailable.
3. Execute the neutral worker from its independent host.
4. Verify the receipt reports identical source and target SHAs.
5. Start the GitLab validation pipeline on that mirrored ref.
6. Verify mirror parity is `HEALTHY`.
7. Require the Python governance profile and Broker profile to pass.
8. Record GitLab provider evidence with the mirrored SHA.
9. In the authenticated `contingency-evidence` GitLab job, run the provider
   comparison with live verification already established by the job-token
   identity check and final live parity probes. Retain
   `evidence-disposition.json` and require
   `CONTINGENCY_EVIDENCE_ONLY` when primary GitHub CI evidence is unavailable.
10. Confirm no merge authority has been granted by the contingency result.

Expected outcome:

```text
mirror_parity          = HEALTHY
gitlab_ci              = PASS
evidence_disposition   = CONTINGENCY_EVIDENCE_ONLY
github_authority       = AUTHORITATIVE
gitlab_authority       = NONE
```

## Scenario B — mirror divergence

1. Use an isolated non-production target ref.
2. Introduce a target commit that is not an ancestor of the selected GitHub ref.
3. Execute the neutral worker.
4. Require the worker to reject the synchronization before any overwrite.
5. Evaluate parity and require `DIVERGED`.
6. Run GitLab validation only for diagnostic evidence if desired.
7. Reject that GitLab evidence from cross-provider corroboration.
8. Preserve the divergent ref for investigation; never force-overwrite it as part
   of the drill.

Expected outcome:

```text
mirror_parity          = DIVERGED
evidence_eligible      = false
automatic_overwrite    = false
github_authority       = AUTHORITATIVE
```

## Retry matrix

Only infrastructure availability has bounded retry semantics:

| Failure class | First attempt | At configured limit |
| --- | --- | --- |
| `PROVIDER_INFRA_FAILURE` | `RETRY_ELIGIBLE` | `RETRY_LIMIT_REACHED` |
| `RUNNER_ASSIGNMENT_FAILURE` | `RETRY_ELIGIBLE` | `RETRY_LIMIT_REACHED` |
| `CODE_FAILURE` | `NOT_RETRY_ELIGIBLE` | `NOT_RETRY_ELIGIBLE` |
| `POLICY_FAILURE` | `NOT_RETRY_ELIGIBLE` | `NOT_RETRY_ELIGIBLE` |
| `MIRROR_FAILURE` | `NOT_RETRY_ELIGIBLE` | `NOT_RETRY_ELIGIBLE` |
| `UNKNOWN` | `NOT_RETRY_ELIGIBLE` | `NOT_RETRY_ELIGIBLE` |

No retry decision in this runbook changes authority or converts a failed code,
policy, or mirror validation into success.

## Closure evidence

A successful drill package contains only non-secret artifacts:

- mirror receipt with exact source/target SHA;
- mirror-parity result;
- canonical validation result;
- provider evidence record;
- `evidence-disposition.json` generated by the authenticated GitLab evidence job;
- timestamp and test-ref identity.

Secret stores, credential helpers, environment dumps, and token-bearing logs are
not drill artifacts.
