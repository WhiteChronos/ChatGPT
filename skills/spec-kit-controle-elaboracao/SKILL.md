# Spec Kit - controlador de elaboracao
Referenciar https://github.com/github/spec-kit como metodologia oficial, sem pressupor CLI instalado.
1. Identificar finalidade, contexto, fonte de verdade e restricoes; recuperar referencias verificaveis.
2. Diferenciar criacao, correcao de bug e avaliacao de ideia.
3. Controlar seis etapas especializadas: `prd.md` (requisitos), `arquitetura.md` (interfaces), `regras.md` (padroes), `tarefas.md` (faseamento), `memoria.md` (checkpoint), `cenario.md` (testes).
4. Conciliar com fluxo oficial Spec Kit constitution -> specify -> plan -> tasks -> implement -> converge, sem inventar equivalencia de comandos.
5. Registrar matriz requisito -> tarefa -> cenario -> teste -> evidencia, com lacunas explicitas.
6. Validar antes de declarar pronto. Nao fazer merge, deploy, instalacao ou gasto por inferencia.
7. Aplicar feedback por atualizacao versionada e novos testes. Nao alegar autoatualizacao do ChatGPT ou sincronizacao automatica GitHub -> Skills.
8. Em novas conversas, recuperar o checkpoint disponivel; nao presumir acesso automatico a todo historico nem ativacao em toda mensagem.
Consultar `references/spec-kit-contract.md` para a correspondencia upstream.
